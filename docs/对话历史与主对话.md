# 对话历史与主对话

## 入口与操作

- 应用首页顶部的历史图标、“查看对话历史”或“管理对话与新建”。
- 双击桌宠打开聊天窗口，点击输入区下方的“历史”。关闭输入窗口跳转时会保留草稿。

历史页面可以筛选佩丽卡、彩叶、明日奈、辉夜、白子；查看其它角色的记录不会更换桌面角色。

| 操作 | 行为 |
| --- | --- |
| 查看记录 | 打开所选对话，查看用户消息、模型回复、时间和可折叠的思考过程；支持选择复制文字 |
| 设为主对话 | 每个角色分别保留一个主对话；点击记录卡片不会自动设为主对话 |
| 新建 | 可输入对话名称，留空则使用“对话 N”；新建后设为该角色的主对话，旧记录保留 |
| 删除对话 | 删除确认后移除整段对话；删除主对话时选择该角色另一条最近更新的对话，最后一条删除后创建空白主对话 |
| 删除一轮 | 通过消息上的删除按钮，一起删除本轮用户消息、回复与思考；主动搭话只删除该条回复 |

删除操作无法撤销。记录已删除后，旧请求的迟到回复不会将其重新写入。

## 保存与上下文

用户发出的消息、模型回复和主动搭话都记录到请求开始时选定的主对话，并保存于应用私有目录 `files/conversations/history.json`。关闭应用或重新启动桌宠服务后仍可查看。文件使用 Android AtomicFile 写入；读取失败时报告错误，不用空记录覆盖原文件。

“人设与对话”中的“多轮对话（记忆上下文）”开关仍有效：

- 开启：后续请求带当前角色主对话中已完成的问答正文。
- 关闭：请求只带当前消息，人设和可选时间信息照常发送；历史仍继续保存。
- 历史页面提示关闭状态，并提供“开启多轮上下文”快捷操作。

思考过程独立保存以供查看，不作为聊天正文发送。请求时间戳只存在于当次请求中，不写入历史。每条记录的显示时间为本地创建时间。

发送前先保存用户消息及一个回复占位记录；成功后填入完整正文与思考，失败或取消时保留原消息并标记状态。未完成、失败和取消的问答不进入模型上下文。应用进程异常终止时，未完成的占位记录显示“回复尚未完成”。

在请求期间切换主对话，原回复仍归属于请求开始时的对话。删除原对话或原问答后，回复不再落库。

旧版本只有服务内存中的临时消息，无法补回已丢失的旧记录；持久历史从更新后的新消息开始保存。

## 验证

测试覆盖序列化恢复、角色隔离、主对话切换、删除主对话和最后一条、迟到回复、删除整轮、失败 / 取消上下文过滤、主动搭话及写入失败保护。历史列表、详情、删除确认和输入窗口跳转仍需实机复核。
